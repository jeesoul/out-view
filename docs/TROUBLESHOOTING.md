# 长连接与固定端口排错

## 先确定断开的层级

记录发生时间、服务端/客户端版本、客户端状态、映射端口和日志。分别检查：

1. CLI/GUI 是否仍显示注册成功，后台是否能看到在线设备。
2. 心跳时间是否更新；是否出现读超时、heartbeat acknowledgement timeout、write timeout 或重新注册。
3. 固定映射是否存在，状态是在线还是“离线 · 端口保留”。
4. 被控电脑本机 `127.0.0.1:local-port` 是否仍可访问。
5. 只有 mstsc 断开时，检查 Windows RDP 会话时限、电脑睡眠和系统日志。

`/health` 只表示 HTTP 应用能响应，不能独立证明控制端口和 RDP 可用。应同时核对 Netty 启动日志与一次真实数据往返。

## 1.2.1 已定位的代码问题

| 触发条件 | 原行为 | 修复方向 |
| --- | --- | --- |
| 首次连接时服务器不可达 | 尚未启动重连循环就返回 | 自动重连模式首次拨号也由后台恢复 |
| 链路半开、对端无响应 | 控制读取或写入可长期阻塞 | 读写、注册及心跳应答期限 |
| 本地 RDP/服务停止读数据 | 同步本地写拖住控制读循环 | 每连接独立拨号/写入与有界队列 |
| 外部连接关闭 | 本地 socket 缺少关闭通知而残留 | 双向 type 7 和幂等资源清理 |
| 旧连接或旧 manager 延迟回调 | 可能影响新一代连接 | 所有权校验、顺序恢复和取消控制 |
| 新监听失败 | 固定映射被删除或后台仍报成功 | 保留预留，失败回滚到旧监听 |
| 在线修改外网端口 | 会话与设备查询仍返回旧值 | 同步数据库、会话、查询和注册 ACK |
| GUI 停止被控服务 | 停止 ticker 后等待其通道的任务无法退出 | 显式取消并等待状态任务结束 |

这些问题通过可控测试复现。没有现场断开时的日志，就不能把任意一次公网/RDP中断认定为其中某个唯一原因。

## 重连后端口变化

- 先确认设备 ID 未改变。GUI 设备码保存在用户配置目录 `outview/device.json`，更换 Windows 用户或删除该文件会改变身份来源。
- 同一设备ID只运行一个被控客户端。两个常驻实例使用相同ID会替换彼此的会话并反复重连，应检查重复启动的GUI/CLI和登录自启动项。
- 确认启动日志加载了原固定预留。数据目录变动会让服务读取新的 H2 文件。
- 使用 `OUTVIEW_DATA_DIR` 的绝对路径，并检查外部 application.yml 有没有覆盖数据库 URL。
- 后台“删除预留”会允许重新分配；“断开”和“封禁”保留预留。
- 端口被其他程序占用时，本版本拒绝注册/修改并保留预留，不会偷偷换端口。

## 仍显示在线但远程不能连接

检查本地目标端口、控制与数据端口网络连通性、RDP服务状态以及客户端日志。心跳在线表示控制连接活动，不证明目标服务健康。看到 local service dial/write 错误时优先检查本机目标服务。

单条接收端过慢导致队列超限时，该条转发会关闭；这样可以保护其他连接和心跳。应定位慢服务或网络拥塞，再考虑有依据地调整队列限制。

## 收集可用证据

客户端可设置 `OUTVIEW_LOG_LEVEL=DEBUG`，服务端可临时使用 `--logging.level.com.outview=DEBUG`。记录同一时间段的两端日志、版本、设备 ID、配置端口、断开前最后一次心跳及重连结果；分享前去除密码和 Token。

用 [开发指南](DEVELOPER_GUIDE.md) 中的 soak 脚本在本机复现，再在自己的测试环境逐步增加真实网络环节。不要运行 `test/nat` 或旧弱网脚本后，把模拟输出当作完整公网验证。
